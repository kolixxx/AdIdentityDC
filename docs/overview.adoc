= Overview
:toc: left
:toclevels: 3
:sectnums:

== Назначение продукта

Продукт позволяет писать правила межсетевого экрана OPNsense не только по IP-адресам, но и по **группам Active Directory** (и опционально по отдельным пользователям).

Типичная формулировка политики:

* разрешить трафик от группы `Managers`;
* запретить трафик от группы `Interns`;
* (опционально) разрешить трафик от конкретного пользователя.

С точки зрения OPNsense правила по-прежнему работают по IP. Продукт поддерживает актуальную связку `user <-> ip <-> group` и проецирует её в **Aliases**.

== Проблема, которую решаем

В IP-пакете нет информации о пользователе и группе AD.  
Firewall умеет принимать решения по IP/портам/протоколам, но не по identity напрямую.

Если появится актуальная связка:

[source]
----
user  <->  ip  <->  group
----

то группу можно представить как Alias со списком текущих IP залогиненных пользователей этой группы. Тогда администратор пишет правило по имени группы, а firewall фактически фильтрует по IP.

== Высокоуровневая идея

. Пользователь входит на доменный ПК.
. Domain Controller фиксирует событие аутентификации (`user + ip`).
. Agent на DC обогащает запись группами через LDAP.
. Agent передаёт сессию в Plugin на OPNsense.
. Plugin обновляет Aliases.
. Администратор использует эти Aliases в обычных Firewall Rules.

IMPORTANT: Plugin **не создаёт** firewall rules. Политику доступа пишет администратор.

== Компоненты

[cols="1,2"]
|===
|Компонент |Роль

|**Windows Agent**
|Служба на Domain Controller. Читает события входа, резолвит группы, хранит state сессий, отдаёт данные в Plugin.

|**OPNsense Plugin**
|Принимает сессии, поддерживает внутренний state, создаёт/обновляет Aliases для групп (и опционально для пользователей).

|**Aliases (OPNsense)**
|Списки IP, которые администратор использует в Firewall Rules.

|**Firewall Rules**
|Обычные правила OPNsense, написанные администратором.
|===

== Что даёт продукт

* Group-based firewalling через Aliases.
* Опциональные user aliases (один пользователь = один IP alias).
* Актуальная картина "кто сейчас залогинен и откуда".
* Разделение ответственности: identity-синхронизация отдельно, политика безопасности отдельно.

== Пилотный scope (v1)

Первая версия ориентирована на пилот:

* один Domain Controller;
* один Agent на этом DC;
* group aliases как обязательный режим;
* user aliases как опция в Plugin;
* канал Agent -> Plugin (push) + полный resync по запросу;
* без multi-DC collector (будет отдельным этапом).

== Что продукт не делает в v1

* не пишет firewall rules автоматически;
* не является полноценным NAC/802.1X решениемнием;
* не гарантирует мгновенное определение logout (используется TTL/aging);
* не покрывает несколько DC без дополнительной прослойки-коллектора.

== Базовый пользовательский сценарий

. Администратор устанавливает Agent на DC и Plugin на OPNsense.
. В Plugin указывает, какие AD-группы синхронизировать в Aliases.
. Пользователь из группы `Managers` логинится на ПК `10.10.20.55`.
. Alias `Managers` начинает содержать `10.10.20.55`.
. Администратор уже заранее (или после) создаёт правило:  
  `Allow source=Managers -> ...`
. Трафик пользователя начинает попадать под это правило.

== Термины

[cols="1,2"]
|===
|Термин |Смысл

|Session / mapping
|Запись `user + ip + groups (+ meta)`.

|Group alias
|Alias OPNsense с именем группы; содержимое = IP участников группы, которые сейчас "активны".

|User alias
|Опциональный Alias на одного пользователя; обычно содержит один IP.

|Push
|Agent сам отправляет изменение сессии в Plugin.

|Pull / Resync
|Plugin запрашивает у Agent полный текущий state.

|TTL
|Время жизни сессии при отсутствии подтверждённого logout.
|===
