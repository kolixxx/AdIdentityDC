== Event ID (шпаргалка)

[cols="1,2,2"]
|===
|ID |Смысл |v1

|4768
|Kerberos TGT request
|Основной

|4769
|Kerberos service ticket request
|Refresh существующей сессии с тем же user + IP; при `ActivityRecreateEnabled`
также восстанавливает истёкшую сессию для запомненного логона (D23)

|4624
|Successful logon
|Дополнительный

|4776
|NTLM auth
|Не поддерживается. Событие сообщает `Workstation` (NetBIOS-имя) и не содержит
адреса клиента, поэтому сессию из него получить нельзя — поддержка убрана
в D27, а не оставлена флагом-пустышкой

|4634 / 4647
|Logoff
|Не используется. Выход на рабочей станции пишется в журнал **этой станции**,
а не DC; на контроллере такие события отражают лишь разрыв сетевых логонов
к самому DC. Старение сессий построено на TTL — см. D26
|===

== Фильтры drop (must)

* username заканчивается на `$`
* `ANONYMOUS LOGON`, `SYSTEM`, аналоги
* IP пустой / `-` / `127.0.0.1` / `::1`

== Pilot contract v1 (зафиксировано)

Working name:: `AdIdentity`  
OPNsense module:: `OPNsense\AdIdentity`  
Auth:: `Authorization: Bearer <shared_token>` (один token на Agent <-> Plugin)

=== Session object

[source,json]
----
{
  "user": "ivanov",
  "domain": "CORP",
  "ip": "10.10.20.55",
  "groups": ["Managers", "Office-Users"],
  "event": "login",
  "ts": "2026-08-02T15:40:00Z",
  "dc": "dc01.corp.local",
  "expires_at": "2026-08-02T23:40:00Z"
}
----

[cols="1,1,2"]
|===
|Поле |Обязательность |Смысл

|`user`
|required
|sAMAccountName

|`domain`
|required
|NetBIOS или DNS domain

|`ip`
|required
|IPv4 клиента (v1)

|`groups`
|required (может быть `[]`)
|группы после LDAP; желательно уже пересечённые с allowlist

|`event`
|required
|`login` \| `refresh` — единственные значения, которые формирует агент
и принимает плагин

|`ts`
|required
|ISO-8601 UTC

|`dc`
|optional
|имя DC-источника

|`expires_at`
|optional
|если нет — Plugin считает от TTL
|===

NOTE: Значение `refresh` приходит из двух разных источников, и по одному полю
`event` их не различить. Активность по 4769 (D22) сдвигает и `ts`, и
`expires_at`. Периодический re-push (`ReconcileIntervalSec`, D7) сохраняет оба
значения без изменений и меняет только `event`. Поэтому в `session-list`
признак свежей активности — сдвинувшийся `expires_at`, а не сам `refresh`.

=== Plugin API (принимает push)

Base:: `/api/adidentity`

[cols="1,2"]
|===
|Endpoint |Смысл

|`POST /api/adidentity/session/upsert`
|создать/обновить сессию + aliases

|`POST /api/adidentity/session/remove`
|удалить сессию/IP binding

|`GET /api/adidentity/session/list`
|локальный список сессий Plugin (debug/UI)

|`POST /api/adidentity/service/reconfigure`
|применить настройки Plugin: перегенерировать шаблоны, зарегистрировать cron-задачу
истечения сессий (D5) и сразу выполнить resync с агента. Остаётся успешным, даже
если агент недоступен — тогда в ответе появляется `resync_warning`

|`POST /api/adidentity/service/resync`
|ручной полный resync Plugin <- Agent (кнопка «Resync from Agent» в UI).
Только POST
|===

`remove` body:

[source,json]
----
{
  "user": "ivanov",
  "domain": "CORP",
  "ip": "10.10.20.55",
  "reason": "ttl_expired"
}
----

`reason`: `ttl_expired` | `manual_remove` | `logout` | `resync`

IMPORTANT: Endpoint реализован с обеих сторон, но **агент его сегодня не
вызывает вообще** — в production-коде есть только `upsert`. Сессия на плагине
исчезает исключительно по TTL, поэтому перечисленные `reason` пока
не встречаются в реальном трафике. Последствия этого разобраны в D26.

=== Agent API (отдаёт state)

Base:: `/api/v1` на хосте Agent

[cols="1,2"]
|===
|Endpoint |Смысл

|`GET /api/v1/health`
|alive/status

|`GET /api/v1/sessions`
|полный snapshot сессий
|===

`health` (минимум):

[source,json]
----
{
  "status": "ok",
  "version": "0.1.0",
  "sessions": 42
}
----

`sessions`:

[source,json]
----
{
  "sessions": [ { "...": "session object" } ]
}
----

Транспорт:: main = push Agent→Plugin; backup = resync Plugin→Agent (`GET /api/v1/sessions`) on start/manual/repair

=== Alias naming

Нормализация имени:

* только `A-Za-z0-9_`;
* прочие символы → `_`;
* схлопнуть повторные `_`;
* обрезать края `_`;
* должно начинаться с буквы (если нет — префикс `g_` / `u_`).

[cols="1,2,2"]
|===
|Тип |Имя |Содержимое

|Group alias
|нормализованное имя AD-группы (`Managers`, `Office_Users`)
|IP активных пользователей группы

|User alias (opt)
|`u_` + нормализованный `user` (настраиваемый prefix)
|обычно 1 IP
|===

Операции: точечные add/delete IP; full rebuild только на resync/repair.

=== Минимальный UI Plugin

Обязательные настройки:

* `enabled`
* `shared_token`
* `agent_base_url` (для health/resync)
* `monitored_groups` (список, one-per-line)
* `enable_user_aliases` (default off)
* `session_ttl_sec` (default `28800` = 8h)

Опционально / advanced:

* `user_alias_prefix` (default `u_`)
* `auto_create_aliases` (default on)

=== Минимальный конфиг Agent

Имена — как в `appsettings.json` (секция `Agent`), совпадают со свойствами
`AgentOptions`:

* `PluginBaseUrl` (например `http://10.0.1.254` — базовый URL, путь
  `api/adidentity/session/upsert` агент добавляет сам)
* `SharedToken`
* `ListenAddr` (default `+`) / `ListenPort` (default `8443`)
* LDAP: host, bind, base DN
* `monitored_groups`
* `session_ttl_sec`
* event profile: `4768` + ограниченный `4624`

== Быстрая диагностика (1 минута)

. Пользователь залогинен?
. Есть event на DC?
. Есть session в Agent?
. Push accepted Plugin?
. IP есть в group alias?
. Firewall rule использует этот alias и стоит в нужном порядке?

Если где-то "нет" — чинить этот слой, не следующий.

== Чего продукт не делает

* не пишет firewall rules сам;
* не заменяет 802.1X/NAC;
* не считает logoff идеальным сигналом;
* не закрывает multi-DC без коллектора в v1.
